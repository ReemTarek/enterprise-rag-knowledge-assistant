# Phase 2b Hardening — UI Defect Fixes and Playwright E2E Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the defects found by the real-browser verification of Phase 2b and add a maintained, CI-run end-to-end test suite (`@playwright/test`) that exercises the Angular client against the real API and SQL Server, so UI regressions are caught automatically before merge.

**Architecture:** E2E tests live in `frontend/enterprise-rag-web/e2e/` and run full-stack: SQL Server (Docker locally, a service container in CI) → migrated database → API in Release → Angular dev server with the same-origin proxy → Chromium driven by Playwright. Test data is created through the public API in a global setup (seeded admin → forced password change → users/KBs), never by writing to the database. Accessibility is checked with `@axe-core/playwright` (serious/critical violations fail). No network mocking for the main flows; `page.route` is used only to simulate an unreachable API.

**Tech Stack:** `@playwright/test` (Chromium project), `@axe-core/playwright`, existing Angular 22 app, ASP.NET Core API, Docker Compose SQL Server, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-enterprise-rag-design.md`; predecessor plan `docs/superpowers/plans/2026-11-23-phase2b-angular-shell.md`; defect evidence: real-browser report (findings copied below).

## Defects to fix (from the real-browser verification, 2026-11-27)
- **D1 (Important):** change-password — the two-line password hint overlaps the "Confirm new password" field (all languages).
- **D2 (Important, a11y):** keyboard focus ring faint/missing on the language button, filled buttons and the paginator select.
- **D3 (Important, a11y):** member role `mat-select` is announced only by its value ("Owner"), not "Change role of <name>".
- **D4 (Minor, RTL):** Latin names/emails in tables are not direction-isolated in Arabic (e.g. a trailing `>` renders at the wrong end).
- **D5 (Minor, RTL):** email inputs run right-to-left in Arabic.
- **D6 (Minor):** browser Back while the temporary-password dialog is open changes the page behind it (dialog stays). → **Deferred**: documented as a known limitation (dialog stays by design; route change underneath is harmless).
- **D7 (Minor/Important):** signing out in one tab does not end the session in other open tabs until their access token expires (≤ 15 min).
- **D8 (Minor):** API down behind the dev/reverse proxy returns 502/503/504 without a ProblemDetails body → users see "Something went wrong" instead of the network/unreachable message.
- **A11y-1 (Minor):** axe "region" — toolbar brand outside a landmark.

## Global Constraints
- No changes to backend behaviour except what a task states (none planned).
- E2E suite must be deterministic and isolated: each spec creates its own users/KBs with unique suffixes; no order dependence between spec files; retries in CI = 1 maximum (flakes must be fixed, not hidden); no `waitForTimeout` sleeps — use web-first assertions.
- No secrets committed: E2E credentials are generated per run (env or random in global setup); `.env`, `playwright-report/`, `test-results/`, `e2e/.auth/` are git-ignored.
- Tests use accessible locators (`getByRole`, `getByLabel`) — which also verifies labelling; fall back to `data-testid` only where no accessible name exists (and then add one).
- All existing rules stay: no hard-coded UI strings, no `innerHTML`, no tokens in storage, logical CSS properties, i18n key parity, lint/unit tests green.
- Commit after each task with trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus
1. E2E stability: the suite passes 3 consecutive local runs and in CI without retries masking failures.
2. The suite really runs full-stack (the API is hit; a test fails if the API is down except the explicit "API unreachable" spec).
3. Regression tests exist for D1–D5, D7, D8 and A11y-1 and fail on the pre-fix code (verified by running them before the fix lands, or by a documented mutation).
4. CI job is self-contained (SQL service container, migrations, API start, readiness wait, artifact upload of the HTML report + traces on failure) and does not leak credentials in logs.
5. Cross-tab logout (D7) never transmits secrets between tabs (message carries no token) and doesn't cause redirect loops.
